# 宋磊个人作品集网站设计

## 1. 目标

建设一个面向国内 B 端产品经理岗位的中文个人网站，同时承担长期记录与求职作品展示两项职责。

网站第一印象应当是：专业、可靠、清晰、克制，并具有适度的个人气质。视觉上借鉴 SkyClinics 的大面积留白、低饱和青绿色、雾化空间、细字重和展览式滚动节奏，但不使用音乐、医疗意象、山景复制或影响阅读的炫技交互。

第一版完成标准：

- 桌面端和手机端均可舒适浏览。
- 首页能在 30 秒内说明个人定位、核心能力和代表项目。
- 5 个案例均有清晰入口，其中 4 个为项目案例，1 个为经验专题。
- 支持查看或下载简历，支持跳转至公开代码仓库。
- 动效流畅、克制，并尊重系统的“减少动态效果”设置。
- 页面内容可在后续不改结构的情况下持续补充。

## 2. 目标受众与定位

首要受众：

- B 端产品负责人和用人经理。
- 招聘人员。
- 需要进一步验证候选人能力的研发、项目和业务面试官。

个人定位：

> 具备研发和项目管理背景、长期参与支付与企业系统建设的 B 端产品经理，能够把复杂业务转化为清晰、可靠、可执行的产品方案。

Java、Python、SQL、React、Spring 等技术能力作为产品落地能力的证据，而不是网站的主叙事。网站重点证明业务理解、产品规划、范围取舍、跨团队推动和复盘能力。

## 3. 视觉方向

采用“雾感科技为主、理性系统为辅”的方向。

### 3.1 视觉语言

- 主背景：偏暖的雾白和浅灰绿色。
- 强调色：低饱和深青绿。
- 辅助色：薄荷青、冷灰、少量暖米色。
- 标题：较轻字重、大字号、宽松行高。
- 正文：优先保证中文阅读舒适度，不使用过细字重。
- 卡片：半透明浅底、细边框、轻微背景模糊，不堆叠重阴影。
- 图形：点阵、柔和光晕、流程线和数据结构，不使用无意义插画。

### 3.2 动效原则

- 首屏背景的雾化光晕缓慢漂移，周期长、幅度小。
- 标题、副标题和行动按钮分层进入，总时长控制在约 1 秒。
- 项目卡片进入视口时依次显现，避免整页同时运动。
- 卡片悬停仅进行轻微上移、边框变化和局部信息展开。
- 页面转场保持短促，不制造等待感。
- 不自动播放音频或视频。
- 当系统启用 `prefers-reduced-motion` 时，关闭位移、漂移和视差，仅保留透明度变化或完全静态。

## 4. 信息架构

顶部导航：

- 精选案例
- 工作方法
- 经验沉淀
- 关于我
- 简历

网站首版包含以下页面：

1. 首页
2. 项目案例详情页
3. SaaS 方法与经验专题页
4. 关于我页面
5. 简历查看或下载入口
6. 404 页面

首版不建设后台管理系统、用户登录、评论、搜索、标签筛选和多语言功能。内容采用本地结构化数据维护。

## 5. 首页设计

首页按“建立定位 - 提供证据 - 展示案例 - 说明方法 - 呈现沉淀 - 引导联系”的顺序组织。

### 5.1 首屏

主标题：

> 让复杂业务，成为清晰、可靠、可执行的系统。

辅助介绍说明 B 端产品经理定位、研发与项目管理背景，以及支付、营销和企业管理系统经验。

主要行动：

- 查看代表项目
- 下载简历

可信证据：

- 9 年以上支付行业经验
- 5 个完整案例
- PMP 项目管理认证

简历中的年龄、性别、离职状态和手机号不在首屏展示。联系方式集中放在页尾和关于页。

### 5.2 精选案例

按以下顺序展示：

1. `payment`：电子券营销平台
2. `lifecaregarden`：国寿嘉园支付管理系统
3. `HomeInformationManagementSystem`：房产用户信息管理系统
4. `jpnms`：日本商户管理系统
5. `saaSManagement`：SaaS 与支付经验沉淀专题

`payment` 使用较大的主案例卡片，其余项目采用较紧凑卡片。每张卡片只显示业务问题、核心能力标签和案例入口，不在首页堆叠技术细节。

### 5.3 工作方法

使用四步结构：

1. 理解现场：角色、问题、目标与约束
2. 建立模型：流程、规则、状态与数据
3. 规划取舍：范围、优先级、风险与节奏
4. 推动落地：协作、验收、复盘与迭代

### 5.4 记录与关于

首版提供少量文章或专题入口，用于承接长期记录。没有正式文章时，展示已有的项目复盘与方法沉淀，避免空栏目。

## 6. 项目案例页模板

所有项目使用统一结构，降低阅读成本：

1. 项目一句话概述
2. 项目背景与业务问题
3. 我的角色和职责边界
4. 关键用户与业务流程
5. 目标、约束和成功标准
6. 产品规划与范围取舍
7. 核心方案与关键规则
8. 原型或真实界面展示
9. 技术协作与实现证据
10. 验证结果、项目影响和数据
11. 复盘：如果重新做一次会怎样调整
12. Figma、GitHub/Gitee、文档和演示入口

页面支持三种阅读深度：

- 30 秒：标题、摘要、角色、成果和关键标签。
- 3 分钟：业务问题、核心方案、取舍和结果。
- 深度阅读：流程图、状态机、数据模型、接口与实现证据。

视频演示如暂未制作，首版使用界面截图和步骤式演示图，不放置无法播放的占位播放器。

## 7. 各案例叙事重点

### 7.1 payment

作为第一主案例，重点展示电子券从活动创建、发券、查询、核销到运营统计的完整闭环，以及状态机、预算控制、重复发券、幂等核销和商户隔离等关键规则。

### 7.2 lifecaregarden

重点展示养老支付场景中的交易、退款、通知补偿、对账差错、审计追踪和一期范围控制。

### 7.3 HomeInformationManagementSystem

重点展示如何识别 Excel 与分散文件夹管理的问题，以房号档案为核心对象建立信息模型，并通过 MVP 取舍完成本地工作台。

### 7.4 jpnms

重点展示商户、交易、对账、结算、权限与运营看板之间的复杂关系，以及在复杂系统中进行模块划分、路线规划和风险管理的能力。

### 7.5 SaaSManagement

不按普通项目复述功能。它作为多年经验专题，展示支付资金链路、项目规划方法、功能设计判断、常见风险、决策框架与面试答辩沉淀。

## 8. 技术架构

第一版采用静态前端架构：

- React
- TypeScript
- Vite
- React Router
- CSS 自定义属性与响应式布局
- Motion 或等价的轻量动效方案

内容以 TypeScript/JSON 数据文件维护，图片、流程图和简历作为本地静态资源。首版不引入数据库或 Spring Boot 后端，因为网站没有需要服务端处理的业务能力。

主要模块：

- `SiteShell`：导航、页尾、全局背景与可访问性。
- `HomePage`：首页模块编排。
- `ProjectPage`：读取项目数据并渲染统一案例模板。
- `ExperiencePage`：SaaS 经验专题。
- `AboutPage`：经历、能力、证书与联系方式。
- `MotionProvider`：统一动效参数和减少动态效果处理。
- `ProjectMedia`：截图、流程图、原型链接和演示材料。

## 9. 内容数据流

1. 项目内容存放在独立结构化文件中。
2. 首页读取项目摘要并按固定顺序渲染。
3. 案例页根据路由标识读取完整内容。
4. 媒体资源通过显式清单引用，缺失资源不渲染对应模块。
5. 外部链接统一标识为新窗口打开，并显示其类型。

该结构允许后续新增项目或文章，而无需复制页面组件。

## 10. 异常与降级

- 项目标识不存在时显示定制 404 页面。
- 图片加载失败时显示项目色块、标题和简短说明，不出现破损图标。
- Figma 或代码仓库暂未公开时不显示按钮。
- JavaScript 动效不可用时，所有正文仍保持可见。
- 视频不可播放时提供截图和文字演示路径。
- 移动端关闭较重的视差和模糊效果，优先保证滚动性能。

## 11. 响应式与可访问性

- 主要断点覆盖手机、平板、普通桌面和宽屏。
- 正文最大行宽受控，中文正文不采用过小字号。
- 所有链接、按钮和项目卡片支持键盘访问。
- 使用语义化标题层级、清晰焦点样式和有意义的图片替代文本。
- 颜色对比满足正常文本可读性要求。
- 导航在移动端简化为紧凑菜单，但保留“精选案例”和“简历”快捷入口。

## 12. 验证方案

功能验证：

- 所有导航、项目路由、简历和外部链接有效。
- 5 个案例入口顺序正确。
- 缺失媒体、错误路由和外部链接均有合理处理。

视觉验证：

- 检查桌面和手机首屏、项目列表、案例页和页尾。
- 检查文字无截断、卡片无重叠、背景动效不遮挡正文。
- 对比实际页面与确认的“雾感科技 + 理性系统”方向。

动效验证：

- 普通模式下进入、滚动和悬停效果流畅。
- `prefers-reduced-motion` 模式下无大幅位移和持续漂移。
- 低性能移动设备上不依赖高开销的全屏滤镜或持续 WebGL 渲染。

内容验证：

- 网站内容与当前简历一致。
- 项目经历与脱敏重构内容明确区分，不制造未经证实的上线数据。
- 联系方式公开范围在上线前再次确认。

## 13. 首版边界

首版包含完整视觉框架、首页、统一案例页、专题页、关于页、简历入口和已有素材接入。

首版暂不包含：

- 内容管理后台
- 在线运行 5 套完整业务系统
- 登录、评论和消息功能
- 中英文切换
- 自动播放音频
- 复杂 3D/WebGL 场景
- 为尚未准备好的项目虚构截图、数据或结果
