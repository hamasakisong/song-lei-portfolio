# 精选案例锚点导航修复设计

## 目标

让“精选案例”相关入口在 React 单页路由中可靠地回到首页案例区：从首页点击时平滑滚动到案例区；从经验页、关于我页和案例详情页点击时，先回到首页，再平滑滚动到案例区。

## 范围

- 顶部导航的“精选案例”。
- 首页首屏的“查看代表项目”。
- 案例详情页的“返回精选案例”与“继续查看其他案例”。
- 页脚的“返回精选案例”。

## 行为规格

- 目标锚点保持 `id="work"`，不改变精选案例区内容和位置。
- 点击入口后，地址栏为 `/#work`。
- 当目标元素已存在时，使用 `scrollIntoView({ behavior: "smooth", block: "start" })`。
- 当从非首页路由返回时，等待首页渲染并出现 `#work` 元素后再执行一次滚动。
- 用户启用“减少动态效果”时，滚动改为即时定位，避免强制平滑动画。
- 浏览器后退、前进和直接打开 `/#work` 也应定位到案例区。

## 技术方案

新增一个小型 `HashScroll` 路由辅助组件，由 `App` 在 `Routes` 外渲染：

- 使用 `useLocation()` 读取 `location.hash`；
- 在 `location.pathname === "/" && location.hash === "#work"` 时，在下一帧查找 `document.getElementById("work")`；
- 找到元素后按用户的减少动态偏好执行滚动；
- 所有现有案例入口继续使用 `Link to="/#work"`，不分散编写点击处理器。

这样路由、地址栏与滚动逻辑由一个组件负责，避免顶部导航、案例页和页脚发生行为不一致。

## 验收标准

- [ ] 在首页点击“精选案例”或“查看代表项目”，页面平滑定位到案例区。
- [ ] 在经验沉淀、关于我和任一案例详情页点击“精选案例”，回到首页并定位到案例区。
- [ ] 直接访问 `/#work` 时定位到案例区。
- [ ] 浏览器后退、前进后，锚点位置与 URL 一致。
- [ ] 减少动态效果开启时不执行平滑滚动。
- [ ] 现有导航、页面切换和案例链接仍正常可用。

## 非目标

- 不添加滚动监听、滚动进度高亮或新的导航样式。
- 不修改首页背景、案例区卡片内容或项目排序。
